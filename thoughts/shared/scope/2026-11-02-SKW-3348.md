# Scope: SKW-3348

## Restatement

In `sibylline-labs/eris` `packages/socrates-core`, `checkEntry` (`src/doc-surgery.ts`) and the doc-entry
renderer (`src/render.ts` `renderDocEntry`) share one entry-title-line parse, so `applyOps` never counts the
leading `` `<id>` `` handle against the 80-character limit and render refuses exactly what `applyOps` refuses.

- **title rule:** `parseTitle` on the bare title: one line, 1–80 chars after trim, nothing Linear autolinks.
  The same rule Olympus SKW-2544 enforces at `POST /v1/socrates/submit` (bare title, `parseTitle` +
  `ENTRY_TITLE_MAX_LENGTH`, both imported from `eris/socrates-core`, so both stay exported).
- **handle:** the readable entry ID `renderDocEntry` prepends as `` `ACME-D10` `` (shape `checkHandle` accepts).
  A hash handle renders as a `hash:` field, not in the title line.

No comment overrides the description. Context from the loop brief: rung first (one shared parse, not a
second lower limit), keep the rule identical to SKW-2544, do not merge.
